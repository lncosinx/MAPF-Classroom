# M4 验收报告：分组比拼（2026-10-28）

M4 的目标是分组比拼：多组并行、排行榜、"全 AI 队"和"专家队"参照行、投屏页。
**验收**：8 组并行跑一轮。**已通过**：压测中一轮从全员提交到推送完成，p95 为 66 ms，目标是 < 1 s；用户也在浏览器里手测通过。

## 1. 模块

| 文件 | 职责 |
|---|---|
| `classroom/core/session.py` | 重构为多组：`Classroom.groups`，用 `group_of` 记录每人在哪组；每组一个 `GroupOut` 推送代理；均分、随机分组、中途加入、按组移除；排行榜和投屏推送 200 ms 去抖；后台计算参照行 |
| `classroom/core/leaderboard.py` | 排名：字典序或单个指标，并列同名次；进行中的组按临时指标排名；参照行插在对应位置但不占名次 |
| `classroom/core/reference.py` | 在同一实例上无头跑"全 AI 队"和"专家队" |
| `classroom/core/round.py` | 抽出 `build_preset`（各组和参照行共用，保证是同一实例）；专家改用单独的单线程池 `get_expert_executor()`；载荷里带组名 |
| `classroom/core/settings.py` | 新增 `num_groups`（1–12）、`rank_by`；`expert_time_limit` 默认值从 0.2 改为 0.03（见第 4 节） |
| `classroom/server/{app,hub,protocol}.py` | `/screen` 页面、`/ws/screen`；学生消息按组路由；`Hub` 去掉全局的 `player_of` |
| `static/teacher/` | 组切换条和"全部"缩略图；座位下拉框改为"第几组·几号"；拖拽分座位落在当前组；单组立即结算；排行榜卡片；投屏开关 |
| `static/screen/` | 投屏页：大字号排行榜、进度条、星星和奖杯（简洁模式）、各组卡片 |
| `tools/loadtest.py` | 压测：自己在单独端口起临时服务，用机器人学生测延迟 |

## 2. 协议增量

| 方向 | 消息 | 说明 |
|---|---|---|
| 老师 → 服务端 | `assign{player_id, agent?, group}` | `group` 默认 0 |
| 老师 → 服务端 | `step_now{group?}` | 不带 group 表示所有组 |
| 老师 → 服务端 | `screen{live_maps}` | 比赛中投屏是否也显示全图 |
| 服务端 → 老师 | `classroom` | 新增 `groups`（各组状态）、`leaderboard`、`references`、`screen_live`；`round` 字段等于第 1 组 |
| 服务端 → 老师 | `teacher_state` / `progress` / `resolved` / `comm_event` | 都带 `group` |
| 服务端 → 老师 | `leaderboard{rows, references}` | 去抖推送 |
| 服务端 → 投屏 | `screen{status, leaderboard, groups[...], live_maps}` | `groups[i].map` 只在该组已结束或 `live_maps` 打开时才有 |
| 服务端 → 学生 | `state.group_name` | 多组时是"第 n 组"，单组时为空 |

## 3. 关键口径（与用户确认）

- **分组**：
  - 老师设组数。各组用同一张地图、同样的起终点（同一 preset、同一放置种子），各自独立推进；
  - 开局时，没分组的在线同学按"人最少的组优先"均分，再在组内随机坐空位；
  - 比赛中途加入的同学放进空位最多的组；
  - 新开一局时保留原来的分组和座位，前提是组号、智能体号还在范围内。
- **消息路由**：智能体编号只在组内有意义。每组的 `GroupOut` 用**本组**的座位表找到学生；发给老师的消息带组号。
- **排名**：
  - 默认按字典序：CSR↓ → ISR↓ → SoC↑ → makespan↑；也可以只看某一个指标；
  - 进行中的组按"如果现在结束"的指标临时排名，未到达的按 max_steps 计，标"暂定"；
  - 参照行插在对应位置，但不占名次。全 AI 队是一次 sample 的结果，不是期望值。
- **投屏**：
  - 比赛中只显示进度（步数、到达人数、排名），某组结束后才显示它的全图；
  - 老师可以一键改成"比赛中也显示全图"，适合全图可见的课；
  - 地图下发由服务端裁剪，所以 `/screen` 不需要鉴权，学生自己打开也拿不到地图。

## 4. 压测（验收）

`tools/loadtest.py` 的配置：20×20 random 地图，40 个机器人学生，关 TTA，一轮最多 40 步。机器人收到新一步后等 0–0.3 s 再提交。
延迟口径：从组内最后一人提交，到组内所有人都收到下一步状态。开发机：Ryzen 7535H，12 核。

| 配置 | p50 | p95 | max | 结论 |
|---|---|---|---|---|
| 8 组 × 16 体，专家时限 0.2 s（原默认） | 1302 ms | 1561 ms | 1673 ms | ❌ |
| 8 组 × 16 体，专家时限 0.03 s + 专家单独线程池 | 41 ms | **66 ms** | 178 ms | ✅ |
| 8 组 × 32 体（加压） | 60 ms | 91 ms | 130 ms | ✅ |

**原因**：结算时要等这一步的专家建议（用于记录、揭晓或补位）。LaCAM* 是 anytime 的，会把时限用满，又有全局锁，8 组只能排队：8 × 0.2 s ≈ 1.6 s。
**依据**：课堂规模上，LaCAM 时限从 0.01 s 到 0.2 s，解的质量几乎相同（20×20 random，每档 10 个实例）：

| 体数 | 0.01 s | 0.02 s | 0.05 s | 0.1 s | 0.2 s |
|---|---|---|---|---|---|
| 16（SoC，移动步数） | 239 | 239 | 238 | 238 | 238 |
| 32 | 525 | 523 | 521 | 521 | 521 |

所有时限下都没有失败。所以默认时限改为 0.03 s，另外给专家单独一个线程，不和模型前向抢线程。以后要调大时限，先跑压测。

## 5. 测试

`pytest` 共 144 项全部通过，其中 M4 新增 13 项：
- `test_leaderboard.py` 4 项：字典序、并列、单指标、参照行不占名次、暂定标记；
- `test_groups.py` 8 项：
  - 均分（人数差不超过 1）、组内座位不重复；
  - 各组是同一实例，但模型实例相互独立；
  - 消息按组路由：两组里同一个智能体号的两个学生互不收到对方组的推送；
  - 单组立即结算、各组独立结束；
  - 移除只影响本组；中途加入；改组数时保留范围内的分组；
  - 参照行能算完；比赛中投屏载荷里没有任何地图、位置、目标；
- 端到端 1 项：两组各 2 个学生通过 WS 打完一局；比赛中投屏没有地图，结束后有；排行榜给出名次；数据库按组分开。

## 6. 已知限制与后续

- 各组同时开始、同时结束，不支持单独重开某一组。
- 排行榜只看这一局，不跨局累计。
- 参照行只跑一局；全 AI 队的成绩有随机性，复盘时可以多跑几局（M5 以后再考虑）。
