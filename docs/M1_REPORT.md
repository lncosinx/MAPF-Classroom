# M1 验收报告：单组可玩（2026-10-27）

M1 的目标是一个组能在浏览器里完整玩一局：WS 服务、学生页（迷雾 / 方向键 / 倒计时）、简易老师页（开始 / 暂停）、SQLite 记录。
**验收**：老师页 + 3 个学生标签页玩完一局，`step_decision` 字段齐全。**已通过**：自动化测试和机器人对局都通过了，用户也在浏览器里手测通过。

## 1. 模块

| 文件 | 职责 |
|---|---|
| `classroom/core/settings.py` | `RoundSettings`：一局的全部规则，pydantic 校验，`extra="forbid"`。视野半径只作用于显示层，pogema 的 `obs_radius` 永远是 5 |
| `classroom/core/views.py` | **学生载荷的唯一出口**（`student_view`）和老师上帝视角（`teacher_view`）；`ViewMemory` 记录记忆迷雾 |
| `classroom/core/round.py` | `GroupRound`：异步回合机。整组前向 → 推送视野 → 后台算专家 → 收集提交 → 结算（超时 / 补位）→ 写库 → 揭晓 |
| `classroom/core/session.py` | `Classroom`：玩家（昵称 + 座位号）、座位分配、新开一局、移除同学 |
| `classroom/core/game.py` | M0 的 `GroupGame`，拆出了 `compute_expert()`，让 LaCAM 不挡在关键路径上 |
| `classroom/storage/db.py` | SQLite，每节课一个文件；所有读写走单线程 executor |
| `classroom/server/{app,hub,protocol,__main__}.py` | FastAPI 路由、WS、连接管理、消息校验、启动脚本（打印局域网地址、二维码、防火墙提示） |
| `static/shared/{theme.css,ws.js,grid-renderer.js}` | 色板、自动重连 WS、三端共用的 SVG 地图组件 |
| `static/student/`、`static/teacher/` | 学生页、老师页（Vue 3 global 构建，不需要构建步骤，不引用外网资源） |

## 2. WS 协议

动作编号一律为 0=wait、1=up、2=down、3=left、4=right。

**学生 → 服务端**

| 消息 | 说明 |
|---|---|
| `join{nickname, seat, token?}` | 第一条消息必须是它；带 token 表示重连 |
| `choose{t, action}` | 提交或修改本步动作，结算前可以改 |

**老师 → 服务端**

| 消息 | 说明 |
|---|---|
| `configure{settings}` | 新开一局；比赛进行中拒绝 |
| `assign{player_id, agent?}` | 指定座位，`agent` 为空表示观战 |
| `remove{player_id?}` | 移出同学，为空时移除所有离线同学 |
| `start` / `pause` / `resume` / `step_now` / `end` / `shuffle` / `refresh` | 控制命令 |

**服务端 → 学生**

| 消息 | 说明 |
|---|---|
| `welcome{token, player}` | 加入成功 |
| `state` | 状态、倒计时、提交进度，以及 `view`（由 `student_view` 生成） |
| `progress` | 提交进度 |
| `reveal{t, you, expert, ai}` | 仅"立即揭晓"模式，**本步结算之后**才发 |
| `kicked` | 被老师移除；随后以 4001 关闭连接 |
| `error` | 错误提示 |

**服务端 → 老师**

| 消息 | 说明 |
|---|---|
| `classroom` | 玩家列表、预设图、本局完整状态 |
| `teacher_state` | 本局状态更新 |
| `progress` | 提交进度 |
| `resolved` | 每步实际执行的动作、控制方、是否超时 |
| `error` | 错误提示 |

关闭码：4000 表示同一身份在别的标签页登录；4001 表示被移除；4403 表示老师端鉴权失败。前端遇到这三种都不自动重连。

## 3. 关键口径

- **建议保密**（不变式 8）：teacher / review 模式下，学生在任何时候都收不到建议。immediate 模式下，"你 / 专家 / AI"的对比在**本步结算之后**才发，因为结算前提交还能改。
- **目标显示同 pogema ch2**：默认 `projection`。目标在视野外时，只下发它在视野框边上的投影，算法和 `Grid.get_square_target` 一样：行、列偏移各自截断到 [-r, r]。半径为 5 时，与 pogema 原生观测 ch2 逐格对拍一致（`test_projection_matches_pogema_ch2`）。`visible`（始终可见）留给低年级用。不提供方向向量，因为它的信息比 pogema 多。
- **投影的画法**：投影可能落在墙上或别人身上，这符合 pogema 语义。所以旗子画在智能体上层，投影用灰色空心旗加虚线框，和实心彩色的真目标区分开。老师端的目标旗都带编号。
- **老师端鉴权**：本机直接放行；其他设备要带启动时打印的 `?key=`。
- **重连 token 按标签页保存**（sessionStorage）：同一浏览器开多个学生标签页时互不挤占。代价是关掉标签页再打开会被当作新同学，刷新则不受影响。
- **离线与移除**：离线同学留在列表里，等他重连；老师可以单个移除，也可以一键清除离线同学。被移除者的 token 作废，座位交给补位方。数据库里的历史记录保留。
- **补位**：没人坐的、断线的位置由 `fill_policy` 控制；超时没提交的由 `timeout_policy` 处理。如果全组没有在线学生，每 0.4 s 自动走一步。
- **缓存**：页面和 `/static` 带 `Cache-Control: no-cache`，升级代码后刷新即可拿到新版本。

## 4. 验收

- **自动化测试**：`pytest` 共 78 项全部通过，其中 M1 新增 45 项：
  - 防泄露 24 项：各种半径、迷雾和目标显示模式，回合机发出的全部消息里不含建议，投影与 pogema ch2 对拍；
  - 回合机 13 项：结算时机、超时、补位、断线接管与交还、暂停、写库字段；
  - 端到端 8 项：老师 + 3 个学生用 WS 打完一局后查库，另含鉴权、重连、移除 / 踢出、配置投影后学生收到投影、静态资源不引用外网、no-cache。
- **机器人对局**：`tools/play_bots.py` 对运行中的服务用 3 个机器人打一局，22 步全员到达；`step_decision` 共 110 行，其中学生 66 行，字段齐全。
- **浏览器手测**：用户用老师页 + 3 个学生标签页玩完，通过。

## 5. 试用中发现并修复的问题

| 现象 | 原因 | 修复 |
|---|---|---|
| 学生能看到目标的具体位置 | 设计时 `visible` 作为默认值，`arrow` 下发方向向量，两者都比模型拿到的信息多 | 改为 pogema 投影，并加对拍测试 |
| 选了投影、应用规则后不生效 | **服务没有真正重启**：旧进程占着端口，新进程报 `address already in use` 后退出；旧代码拒绝了新选项，表单随后被静默覆盖 | 正确停掉旧进程并重启。老师页在应用失败时保留表单，并常驻显示原因。CLAUDE.md 记下重启的注意事项（不用 `pgrep -f`） |
| 关掉网页的同学删不掉 | 只有重连机制，没有移除功能 | 增加单个移除和清除离线；在线同学被移除时会收到通知 |
| 三个学生只有一个看得见投影 | 投影格被别的智能体盖住，或落在墙上时颜色太淡 | 旗子画在上层；有人站在格上时缩小到右上角 |
| 投影太鲜艳，容易被当成目标 | —— | 改成灰色空心旗 |
| 同色目标分不清是谁的 | 色板只有 7 色，会重复 | 老师端目标旗加编号 |

## 6. 已知限制与后续

- 只有一个组；多组、排行榜、投屏页在 M4。
- 简洁模式只做了按钮放大，动物头像、只用图标、彩带等在 M6。拖拽分座位、地图编辑器、课例模板在 M3。复盘和导出在 M5。
- 前端没有自动化的浏览器测试，只做了 node 语法检查和 Vue 模板编译检查（命令见 CLAUDE.md），界面问题要靠手测发现。
- 性能目标（8 组 × 16 体，一轮 < 1 s）留到 M4 的 `tools/loadtest.py` 再测。单组实测：16 体每步前向约 12 ms。
