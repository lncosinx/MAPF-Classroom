# M3 验收报告：老师工具（2026-10-28）

M3 的目标是让老师自己准备地图和规则，内容包括生成器、编辑器、地图库、校验、规则面板、揭晓模式、补位方式。后三项在 M1 已经有了。
用户另外选定一起做：课例模板、拖拽分座位、AI 能力提示。
**验收**：编辑器里画出的图可以直接开局。**已通过**：自动化端到端测试和临时服务上的冒烟测试都通过了，用户也在浏览器里手测通过。

## 1. 模块

| 文件 | 职责 |
|---|---|
| `classroom/maps/mapio.py` | `MapSpec`（标题、地图行、起终点，unpadded 坐标）；pogema 字符串和 JSON 的导入导出 |
| `classroom/maps/library.py` | 内置图、老师保存的图（`my:` 前缀）、课例模板（内置 `lesson:*` 和用户 `mytpl:*`）；`preset_from_spec` |
| `classroom/maps/presets/lessons.json` | 4 个内置课例 |
| `classroom/maps/ai_hint.py` | 按地图形状判断是不是迷宫类，给出 AI 能力提示 |
| `classroom/core/settings.py` | `custom_map: Optional[MapSpec]`，有值时优先于 `preset` |
| `classroom/server/teacher_rpc.py` | 老师 WS 上的请求-应答：地图工坊、地图库、模板 |
| `static/teacher/workshop.js` | 地图工坊组件：生成器、编辑工具、实时校验、地图库、导入导出 |
| `static/teacher/app.js` | "课堂 / 地图工坊"标签页、课例模板、拖拽分座位、AI 提示条 |

## 2. 老师 RPC

请求格式是 `{"type":"rpc","id","method","params"}`，回复是 `rpc_result{id,result}` 或 `rpc_error{id,message}`，错误信息都是中文。

| 方法 | 参数 → 结果 |
|---|---|
| `map.generate` | `{kind, width, height, density, seed}` → `{map}`；kind 取 random / maze / warehouse / house |
| `map.place_random` | `{map, n, seed}` → `{agents_xy, targets_xy}`：在最大连通区里放 n 对，格子互不重叠 |
| `map.validate` | `{spec}` → `{errors, ai_hint}` |
| `map.save` / `map.delete` / `map.load` | 保存（要先通过校验）/ 删除（只能删自己保存的）/ 载入（内置图或自己保存的图） |
| `map.import` / `map.export` | `{text}` → `{spec, errors, ai_hint}` / `{spec}` → `{format, text}` |
| `template.save` / `template.delete` | 把当前规则（含地图）存成模板 / 删除模板 |

会改动地图库或模板的方法执行完后，服务端会再推一份 `classroom` 快照，里面包含 `maps`、`templates`、`defaults`。

## 3. 关键口径

- **导入导出**：
  - 能用 pogema 字符串（`.`、`#`，小写字母是起点、大写字母是终点）就用字符串，导入时直接调 pogema 的 `GridConfig.str_map_to_list` 解析；
  - 超过 26 对，或某对的起点正好是另一对的终点（一个格子写不下两个字母）时，改用 JSON；
  - 尺寸上限 64×64，最多 64 对。
- **存放位置**：老师保存的图和模板放在 `<data>/maps/`，跨课堂长期可用，不入库。文件名由服务端生成，读写前用正则核对，杜绝路径穿越。
- **直接开局**：工坊里没保存的图作为 `custom_map` 下发；校验不通过就拒绝；随 `settings_json` 写进课堂记录，便于复现；整张图不会发给学生。
- **课例模板**：叠加在**默认规则**上，而不是叠加在当前表单上，保证效果和模板说明一致。

| 课 | 地图 | 视野 / 目标 | 通信 | 揭晓 / 界面 |
|---|---|---|---|---|
| 第 1 课 单人找路 | four-rooms 8 体 | 全图可见 | 关 | 立即揭晓，简洁模式 |
| 第 2 课 迷雾中找路 | fog-maze | 半径 2，记忆地图，目标投影 | 关 | 只给老师 |
| 第 3 课 狭路相逢 | doorway | 半径 1 | 开，不限次 | 只给老师 |
| 第 4 课 团队大挑战 | pogema-logo 16 体 | 半径 2 | 开，每步 2 次 | 赛后复盘 |

- **AI 能力提示**：看地图形状，不看它是怎么生成的。
  - 可走邻居 ≤ 2 的格子算"走廊格"。各生成器各取 32 张实测走廊格占比：random 0.21–0.40、house 0.13–0.37、warehouse 0.07、maze 0.39–0.87（9×9 平均 0.70）。阈值取 0.45；
  - 面积 ≤ 100 且人数 > 4，给强提示（M0 实测 9×9 迷宫 8 人时，AI 全员到达约 2/3）；面积 ≤ 200 且人数 ≥ 12，给弱提示（13×13 约 80%）；
  - 结果：random 图零误报，9×9 迷宫 8 人时 32 张里至少 28 张会提示，内置图都不提示。
- **编辑操作**：画墙和橡皮支持按住拖动；放起终点时先点起点、再点终点，自动编号配色；橡皮擦到起点或终点时删掉这一对，后面的编号顺延。
- **拖拽分座位**：把同学表里的一行拖到课堂地图的圆点上。格子由鼠标坐标换算，没有改动三端共用的地图组件；下拉框保留，给触屏设备用。

## 4. 验收

- **自动化测试**：`pytest` 共 131 项全部通过，其中 M3 新增 37 项：
  - `test_mapio.py` 13 项：pogema 字符串往返，并用 `GridConfig` 逐项对拍；26 对以上和起点终点重合时改用 JSON；各种错误输入；
  - `test_library.py` 13 项：用户图和模板的读写删、5 种路径穿越输入、内置项不可删、4 个内置课例都能开局、`custom_map` 开局和拒绝；
  - `test_ai_hint.py` 8 项；
  - 端到端 2 项：生成 → 放置 → 校验 → 保存 → 导出 → 导入 → 用 `custom_map` 开局，学生收到视野且载荷里没有 `custom_map`；AI 提示出现在老师端状态里；
  - 静态检查 1 项：样式表里不许出现单独的 `.on`、`.active` 等通用状态类规则。
- **临时服务冒烟**（单独端口）：真实 WS 上走一遍生成（house 14×12）→ 放 6 对 → 校验 → 保存 → 开局，地图文件写到了指定的数据目录。
- **浏览器手测**：用户试用后通过。

## 5. 试用中发现并修复的问题

| 现象 | 原因 | 修复 |
|---|---|---|
| "地图工坊"标签、选中的工具按钮被压扁，字溢出到右下方 | 在线小圆点用了通用类名 `.on { width: 9px; height: 9px }`，而按钮选中状态也叫 `on`。之前"适应窗口"按钮也是这个原因，当时只设最小宽度顶住了，没查到根因 | 小圆点改名为 `online-dot`；加静态测试，禁止裸写通用状态类规则 |
| "删除一对"按钮多余，工具行放不下 | 用户建议 | 删除功能并入橡皮；工具行和"随机放 N 对"排在同一行 |

## 6. 已知限制与后续

- "侦察兵"（单独设某个智能体的视野半径）用户决定暂缓。
- 编辑器没有撤销功能，误操作要靠橡皮或重新载入。
- 地图工坊里的生成参数没有逐个类型细调：maze 的实际尺寸约为 (w//2)*2+1；warehouse 忽略密度。
